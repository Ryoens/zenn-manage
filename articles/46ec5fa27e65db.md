## はじめに
JANOG57 NETCONに参加いただきありがとうございます。
本記事では、私が出題した「Level 2-13」について解説します。

## 問題文
![](/images/46ec5fa27e65db/TyE2kaC723xwFpkapNQRxySZ.png)
あなたは OSPF のネットワークを運用しています。
IPv6 に対応するため、OSPF の設定を少し変更しました。
設定が終わって、PC-01 から PC-02 に ping を送信したところ、IPv6 は繋がるが、IPv4 は繋がらないことが判明しました。
順当に ping を投げたところ、どうやら RT-01 が悪いことはわかっていますが、原因がわからないので直してください。

## 達成条件
- PC-01 から PC-02 に対して IPv4 の通信ができること
    - ping 192.168.2.2

## 制約
- Static Route を設定するのは禁止です。
- OSPF を用いて経路を設定すること
- RT-02、RT-03 は操作不可

## 解説
トラブルの原因はOSPFのバージョン違いによるものでした。
解決方法としてはRT-01に対して既存のOSPFv2の設定を削除し、OSPFv3の設定を新たに投入することで解決します。
特に、IPv4がOSPFv2のままになっているため、OSPFv3に移行させる必要があります。

RT-01にてtcpdumpを実行すると、IPv6のOSPFv3は双方向でHelloパケットが送受信されていますが、IPv4のOSPFv2は片方向(RT-01 → RT-02 or RT-03)しかHelloパケットが送信されていないことがわかります。

そのため、隣接RTでOSPFv2の設定に不備があることでneighborの確立ができていないことが推察されます。
問題文には以下の記載があります。ここから隣接RT(RT-02、RT-03)ではIPv4もOSPFv3に変えたことが考えられます。
`IPv6に対応するため、OSPFの設定を少し変更しました。`

そこで以下のようにOSPFv2の設定を削除し、IPv4もOSPFv3で設定します。
``` diff
# interface
interface Ethernet1
-   ip ospf area 0.0.0.0
+   ospfv3 ipv4 area 0
!
interface Ethernet2
-   ip ospf area 0.0.0.0
+   ospfv3 ipv4 area 0
!
# ospf
- router ospf 1
-   router-id 1.1.1.1
-   network 10.1.2.0/24 area 0.0.0.0
-   network 10.1.3.0/24 area 0.0.0.0
-   max-lsa 12000
!
+ router ospfv3
+   address-family ipv4
+   !
!
```

## 最後に
本問題はIPv4のOSPFバージョンの違いに起因するトラブルですが、本来はIPv6のトラブルを含める予定でした。具体的には対向のIPv6アドレスのプレフィックスが異なっており、対向のプレフィックスを見ながらRT-01のIPv6プレフィックス修正をするという内容でしたが、プレフィックスが異なってもトラブルが発生せず、PC間でIPv6が疎通してしまったため、ボツになりました。
そのため、IPv4だとOSPFはv2とv3の両方があり、そのバージョン違いを題材にしました。
これだけだと、簡単なので、少し難しくするためにRT-01のみ見れるようにしました。
対向RTのconfigは見れなくしてるので若干のエスパー気質はありますが、ログなどからIPv6しか降っていこないことに気づけたら解けたのかなと思います。

これを機にIPv6やOSPFの勉強を始める人が増えたら嬉しいです。
