## はじめに
JANOG57 NETCONに参加いただきありがとうございます。
本記事では、私が出題した「Level 2-6」について解説します。

## 問題文
![](/images/a30ddae1d53952/5bwMKSuMHbbfzoUZwDyJSwNa.png)
ネットワークを勉強中のさくらさんは IS-IS を勉強し始めました。
シングルエリア構成だけで満足できなくなったさくらさんはマルチエリア構成を勉強し始めました。
いろんなサイトを参考にしながら IS-IS のコンフィグを作成しましたが、IS-IS のネイバーは張れているのに ping が繋がらなくなりました。
繋がらなくなっている原因を探して、直してあげてください。

## 達成条件
- RT-01 から RT-04 の Loopback 4.4.4.4 に対して通信ができること
    - ping 4.4.4.4

## 制約
- Static Route を設定追加、及び削除するのは禁止です。
- IS-IS を用いて経路を設定すること
- IS-IS は既存のプロセス (NETCON) を用いること
- 各RTに設定されているIS-ISのレベルは設定不可です

## 解説
トラブルの原因はRT-01が個別経路を保有していないことに起因します。
RT-01で`show isis route`を実行すると、RT-03とRT-04のLoopbackを保有していないことがわかります。
```
df 0.0.0.0/0 [10/115] via 10.1.1.1, GigabitEthernet0/0/0/0, RT-02, Weight: 0
C 1.1.1.1/32 is directly connected, Loopback0
L1 2.2.2.2/32 [10/115] via 10.1.1.1, GigabitEthernet0/0/0/0, RT-02, Weight: 0
C 10.1.1.0/24 is directly connected, GigabitEthernet0/0/0/0
L1 10.1.2.0/24 [20/115] via 10.1.1.1, GigabitEthernet0/0/0/0, RT-02, Weight: 0
```

IS-ISのルーティングドメインは以下のように分類されます
- level1(L1): 同一エリア
- level2(L2): 異なるエリア

RFC2966によると、L1/L2ルータはL2ルーティングで学習したルートをL1 LSP内でL1エリアへ広報します。
しかし、ルーティングループを防止するため、アップ/ダウンビットを定義しています。
このアップ/ダウンビットはIS-ISのTLV（例えばTLV 128, 130, 135など）で設定されています。
そのため、L1/L2 ルータは、アップ/ダウンビットが設定されている L1 ルートを L2 に再広報しないようになっています。
そこで、特定の経路情報をL1エリア内のルータにも詳細に知らせたい場合、L1/L2ルータ(RT-02、RT-03)で 「L2ルートをL1にリーク（再配送）」する設定が必要です。

RT-02、RT-03の両方に対してルートをリークする設定を投入していきます。
```
route-policy PASS-ALL
  pass
end-policy
!
router isis NETCON
  address-family ipv4 unicast
    propagate level 2 into level 1 route-policy PASS-ALL
  !
!
```

RT-01にて`show isis route`を確認すると、RT-03とRT-04の経路を保持していることがわかります。
```

C 1.1.1.1/32 is directly connected, Loopback0
L1 2.2.2.2/32 [10/115] via 10.1.1.1, GigabitEthernet0/0/0/0, RT-02, Weight: 0
```
